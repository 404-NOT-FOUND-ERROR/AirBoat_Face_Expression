# 已验证案例与修补路径

以下案例以原图、源码或测试记录为依据。除注明的用户现象反馈外，本表情支线的验证主要在电脑与浏览器完成；设备最终效果由各主线实屏验收。

| 现象与识别依据 | 修补方法 | 验证/适用范围 |
| --- | --- | --- |
| 实装像只看见过渡 | 检查实际交付文件和播放器的 entry/performance/exit 区间，工作台直接解码交付资源 | 拖进主体检查确有变化，完整播一轮；设备状态机是否采纳另查 |
| 变色时两个脸重影 | 分层插值眼形与位置，主体保留，背景单独变色 | 看过渡各帧，检查共享首尾和打断；不要仅做两张整脸淡入淡出 |
| 新稿变糊 | 核对 480→240→480、硬阈值和最近邻放大链路 | 从 480 母版恢复轮廓与 4 bit 边缘；同帧大图、小屏对照 |
| 单个新文件比原来大 | 区分单眼/全脸、语义共享、进入收尾的重复存储 | 按真实 AFM+目录和去重文件计数，另量运行内存；不要按一个文件推整库 |

| 某个循环表情底色闪烁、冒色块 | 对照 GIF 的逐帧 alpha 与 RGB：透明处仍带有近似背景色，提取器把隐藏 RGB 当成实色装饰 | 确认透明区只属于背景残片后，再用 alpha 限定提取或禁用该语义的伪装饰层；逐帧对比眼白/瞳孔并检查主体、入口、出口背景恒定。含真实彩色装饰的表情要单独拆分 |

| 惊讶下缘被切 | 原图到 y=426，旧提取只保留到 y=394 | 使用完整源图高度，再检查高点、下缘、装饰和画布范围 |
| 大笑从圆眼变月牙不自然 | 圆眼和月牙轮廓直接叠化，瞳孔过早消失 | 下眼睑先抬，连续遮住实色瞳孔，再收成月牙；两次回弹保留轻重 |

## 按层定位，避免改错地方

1. **源稿。** 看原 GIF 的真实帧与边界，记录它原来的动作。源图就缺轮廓时，先局部美术修补。
2. **拆层。** 核对眼白、瞳孔和装饰是否归对眼睛。图层身份跟随对象，不跟随屏幕左右半区。
3. **动作谱。** 检查 `round(progress*(sourceFrames-1))` 是否造成离散跳变。保留动作节点，用相邻源姿态连续采样。
4. **编码。** 检查目标矩形、原始 w/h、4 bit 覆盖、flip 和游程边界；精灵存储尺寸不等于绘制尺寸。
5. **合成。** 每只眼先清空自己的遮罩，绘制眼白后裁瞳孔；另一只眼不能复用残留遮罩。
6. **页面。** 看字幕/状态条、聆听层和离页重绘，确认黑块不是独立叠层。

`expression_source_repair.py` 的圆弧拟合适合本批近椭圆眼形、两个黑瞳孔的源稿。星形、螺旋、闭眼无黑瞳孔或多黑色装饰时，需单独处理；不能推广为所有表情的自动修复器。

## 聆听条的可复用公式

在当前完整表情上计算 `结果 = 背景 + (白色 − 背景) × 覆盖率`，按 RGB565 的通道精度舍入。输入采用主机字节序，在显示面板提交时只交换一次。

只给独立灰度聆听条使用此解释，不能把眼睛的黑瞳孔也当成透明底。局部刷新时，每帧从当前表情重建底图再叠波形，不能在上一帧波形上继续累加。开始、结束、切页都重绘整个旧条范围。

[参考实现与接入](../../../integrations/listen-overlay/README.zh-CN.md)中附头文件和历史补丁。历史验证：65,536 个 RGB565 底色、50 帧×5 底色×2 屏幕、实际 AirBoat 播放器副本的原资源回归。补丁对当前主线是否仍适用，接入前重新核对。
