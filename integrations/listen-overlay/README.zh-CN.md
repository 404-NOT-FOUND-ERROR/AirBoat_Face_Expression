# 聆听条透明合成 · 本地接入卡

日期：2026-11-22。适用 AirBoat / Mosaico 与 DeskBot。两个项目继续使用各自显示所有者；这里只共享灰度覆盖合成算法。

## 现象与原因

旧 `listen.eaf` 是 100×46 像素、50 个画面帧，加 1 个元数据条目。首帧 4,600 个像素全部被 EAF 解码器标为不透明，其中 3,560 个纯黑像素构成底色。原黑色首页会把它藏起来；绿色或彩色表情上会看到黑框。

通用 EAF 解码器将调色板任一非零 BGRA 项视为不透明，灰色也会直接覆盖背景。这次仅在聆听条合成时解释灰度，眼睛瞳孔保持原样。

## 修复逻辑

1. 先绘制当前完整表情，得到 RGB565 目标像素。
2. 再解码原聆听动画当前帧，将灰度当作白色波形的覆盖率。
3. 对波形区域逐像素计算 `结果 = 背景 + (白色 - 背景) × 覆盖率`，按 RGB565 各通道精度取整。
4. 纯黑覆盖率为 0，原表情完整透出；灰色边缘混入底色；白色竖条保持明亮。
5. 聆听结束后移除波形，重新绘制对应区域。

[参考头文件](listen_overlay_rgb565.h)只负责混合两个 RGB565 像素，无堆内存、全局状态或定时器。输入为主机字节序，面板需要的交换放在最后完成。

## AirBoat / Mosaico 接入

在当前 `app_expression_player_draw()` 的聆听 overlay 分支里，把“覆盖颜色”改成“混合颜色”。示例保留现有 `sample_frame()` 的边界与透明项检查：

```c
uint16_t listen_mask = 0;
if (sample_frame(&player->overlay, logical_x - 130, logical_y - 25, &listen_mask)) {
    color = airboat_listen_over_rgb565(color, listen_mask);
}
```

只在独立 `listen.eaf` 覆盖启用时执行。若当前实现已经使用完整聆听表情且停用旧条，则继续停用，避免重复显示。现有布局为 360 逻辑坐标 `(130,25)`，480 屏按相同坐标映射。沿显示所有者绘制，保留字幕、急停和相机图层顺序。

[AirBoat 补丁](airboat-player.patch)包含头文件与采样替换，已对本轮只读核对的源码通过应用检查。主开发使用自己的当前分支重新检查后再合入。

## DeskBot 接入

在 DeskBot 当前实际使用的绘制层中定位 `listen.eaf` 最终合成点，在脸已经绘入的 RGB565 目标像素上应用同一函数。确认当前源码路径后再落补丁，沿用现有 Emote/GFX 锁、区域重绘、旋转与 flush（提交画面）生命周期。

`SetStatus()` 继续负责聆听状态。逐帧只画波形，不重复触发 `SetEmotion()`、底座动作或字幕刷新。旧波形的黑色矩形区域也要计入刷新范围；开始、结束和切页都重绘旧条区域，避免留下旧像素。

若 GFX 使用局部刷新，背景必须先从当前表情重新合成，再叠加当前波形。反复在上一帧波形上混合会越叠越白。字节交换只在面板提交时做一次。

## 验证与交付

- C 头文件、浏览器参考使用相同 RGB565 舍入。
- 测试覆盖全 65,536 个底色、原动画所有帧、灰度边缘、两种屏幕大小、彩色底色、聆听退出与重开。
- AirBoat 实际补丁已在临时副本编译，原播放器 18 资源 / 1,247 帧、布局与分块重绘通过。可用 `tests/airboat-listen-integration.py --project <airboat-project> --zig <zig.exe> --output <scratch-output>` 复跑。
- 接入后分别做两项目主机回归和目标构建，再检查两台实屏。构建、安装与实屏结果分别记录。
