# 固件接入交接

[English](device-integration.en.md) · [README](../README.zh-CN.md)

## 候选位置

配套 AirBoat 固件目录中的 `projects/airboat_expression_transitions`，分支 `feat/expression-transitions`，基于三路闲时动作提交 `011b565`。CMake 版本为 **1.32.0**，播放器和资源适配为本地候选改动。本仓库发布美术、预演工具、EAF 候选与规范。

## 播放规则

- 绿色 `#28CF60` 是休息状态；进入情绪后独立循环，互动结束回绿色。
- 连续回应从当前可见眼神直接转向下一表情；途中改选接住当时的中间姿态。
- 保留 `app_response → app_expression_player` 单一显示入口。语音、闲时、倾斜和预览继续提交语义。
- 固件采用 28 个文件映射 29 个语义，`neutral`、`idle` 共用 `transition-idle.eaf`；聆听沿用原 API，素材改用整脸片段。
- 评审 EAF 为 240×240、20 fps，附进入／循环／退出区间；设备动态过渡为 360 ms，瞳孔与眼形错开，背景沿较短 HSV 色相路径变化。

## 主开发接手顺序

1. 先读固件仓库的 `AGENTS.md`、固定 SDK 构建流程及最新开发管线。对照主开发最新分支，只合入表情播放器、资源适配、清单、EAF 与主机测试，版本号随主线安排。
2. 先复核内存与耗时。目前有三组紧凑形状掩码、两块 240×240 RGB565 缓冲、源索引及两个解码器，单播放器总预留约 **0.6 MB**；早期“低于 170 KiB”的描述已不适用。核对 S31 实际堆位置、申请失败后的表现和单帧处理时间。
3. 完成固定 S31 构建，记录实际应用／分区体积和更新包哈希，沿用现有分区布局及设备保存参数。
4. 跑共享原生界面检查，再按固件仓库的产品更新流程安装。
5. 实屏体验待机→聆听→思考→回应→待机、途中换表情、点脸与滑动取消、中文字幕、相机进出和连续语音；单独记录帧耗时、空闲堆／最大连续块和重启情况。

浏览器整库形状数据继续用于评审。设备从当次 EAF 解码帧提取有限形状，沿用已有显示所有者。
