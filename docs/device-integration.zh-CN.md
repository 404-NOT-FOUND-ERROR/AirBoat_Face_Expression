## 候选位置

## 播放规则

- 绿色 `#28CF60` 是休息状态；进入情绪后独立循环，互动结束回绿色。
- 连续回应从当前可见眼神直接转向下一表情；途中改选接住当时的中间姿态。
- 保留 `app_response → app_expression_player` 单一显示入口。语音、闲时、倾斜和预览继续提交语义。
- 固件采用 28 个文件映射 29 个语义，`neutral`、`idle` 共用 `transition-idle.eaf`；聆听沿用原 API，素材改用整脸片段。
- 评审 EAF 为 240×240、20 fps，附进入／循环／退出区间；设备动态过渡为 360 ms，瞳孔与眼形错开，背景沿较短 HSV 色相路径变化。

## 主开发接手顺序

1. 先读固件仓库的 `AGENTS.md`、固定 SDK 构建流程及最新开发管线。把提交 `0d087e8dfe2925c96374a5bc07c3cebf9ae5a258`（或相对 `011b565` 的候选差异）审阅后合入最新主开发分支；保留主线当前相机配置和应用改动。
2. 复核内存与耗时。播放器约预留 **0.6 MB**；在合入后的 S31 构建测堆分配位置、申请失败回退、空闲／最大连续块和帧耗时。
3. 用固定 SDK 重建合入后的主线，记录新的应用、UI、分区余量和更新包哈希。隔离候选曾报告 SC101IOT PCLK 延时补丁未应用；按当前可用的相机配置核对后再选择最终包。
4. 跑共享原生界面检查，再按固件仓库的产品更新流程安装。
5. 实屏体验待机→聆听→思考→回应→待机、途中换表情、点脸与滑动取消、中文字幕、相机进出和连续语音；分开记录堆、帧耗时、相机/语音共存、重启和视觉反馈。

浏览器整库形状数据继续用于评审。设备从当次 EAF 解码帧提取有限形状，沿用已有显示所有者。
